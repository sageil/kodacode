Applies multiple edits to a single file in one call.

Usage:
- You must use your `read` tool at least once in the conversation before patching to ensure accurate oldString matching.
- When editing text from Read tool output, ensure you preserve the exact indentation (tabs/spaces) as it appears AFTER the line number prefix. The line number prefix format is: line number + colon + space (e.g., `1: `). Everything after that space is the actual file content to match. Never include any part of the line number prefix in the oldString or newString.
- Use this tool instead of `edit` when you need to make multiple replacements in the same file. This is more efficient than calling `edit` multiple times.
- Every edit in the `edits` array is matched against the original file snapshot from the latest read.
- Edits must be non-overlapping and must not depend on text introduced by another edit in the same patch call.
- Each edit may use either:
  - `range` for an exact 1-based line / 0-based character replacement, or
  - `startLine` / `endLine` to constrain text matching to a smaller region.
- If you previously read the file, pass the latest `<version>` token back as `expectedVersion` so the patch fails cleanly if the file changed since you read it.
- If any edit fails, NONE of the edits are applied. The error will indicate which edit (by index) failed and why.
- The edit will FAIL if `oldString` is not found in the file.
- The edit will FAIL if `oldString` matches multiple locations. Provide more surrounding context to make it unique.
