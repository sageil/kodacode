- Session-scoped task tracker visible in the user's task panel
- CRITICAL: When tasks exist, you MUST update their status as you work:
  1. Set task to "in_progress" BEFORE you start working on it
  2. Set task to "completed" AFTER you finish the work
  3. Never skip these status updates — the user tracks your progress through them
- Actions: "create" (new task), "update" (change status/title/notes/progress by ID), "list" (show all), "delete" (remove by ID)
- Existing task IDs are assigned by Koda and look like `task 1`, `task 2`, etc. Use the exact ID shown in the task panel, or just the number (`1`, `2`) if you prefer.
- Do NOT invent semantic IDs like `task_refactor_backend`. If you are unsure which ID to use, call `task` with `{"action":"list"}` first.
- Tasks created by the planner agent appear automatically — start executing them in order
- Work on one task at a time, but continue through the remaining pending tasks without asking the user between tasks unless blocked: pending → in_progress → completed → next pending task
- Optional `kind` values:
  - `implementation`: code changes that may later be reviewer-checked against acceptance criteria
  - `analysis`: audit/research/review work that should end with a findings summary in `progress`
  - `report`: summary/report deliverables that should end with a report summary in `progress`
- `notes` is optional. For lightweight task tracking, `title` + `status` + `progress` is enough.
- Use `progress` for short status updates such as "audit complete, findings documented" or "blocked on failing tests".
- Treat `notes` as durable task definition and acceptance criteria when that detail already exists, especially for planner-created engineer tasks.
- Do not invent acceptance criteria just to fill the field. Keep `notes` empty unless the user, planner, or existing task definition actually provides durable details worth preserving.
- Do not overwrite existing notes during routine progress updates.
- Before marking an `analysis` or `report` task `completed`, set a short findings/report summary in `progress`.
- Use `replaceNotes: true` only when you intentionally want to replace the stored task definition.
